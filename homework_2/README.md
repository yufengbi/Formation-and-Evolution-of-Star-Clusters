# 作业 2：对比"有无黑洞"两种系统下的演化

**课堂练习**：用 `mcluster` 生成两组 Plummer 星团，用 PeTar 积分 2–3 个弛豫时间，
对比"无黑洞"（单质量）与"有黑洞"（含 10 M☉ 重星）两类系统的差别，
重点考察 **质量迁移（质量分层）** 与 **核心塌缩**。

| 要求（slide） | 本作业实现 |

### 关于"占比 1:9 / 5:5"的取法

slide 上的"调节占比轻/重: 1:9, 5:5"存在歧义（数量比 vs 质量比）。
本作业按 **数量比** 理解，理由是 `mcluster` 的 `-f 6` 多组分模式下的 `-a` 参数
在源码中就是**数量分数**：

```c
/* mcluster/main.c, mfunc == 6 分支 */
noffset[0] = 0;
for (j=0;j<an;j++) {
    noffset[j+1] = noffset[j] + N*alpha[j];   // alpha[] 即 -a 传入的值
}
```

于是：

| 配置 | 轻:重（数量） | 质量组成 | 重星占总质量 | 总质量 M |
|---|---|---|---|---|
| `A_single` | — | 1000 × 1 M☉ | 0% | 1000 M☉ |
| `B_heavy10` | 9 : 1 | 900 × 1 + 100 × 10 M☉ | 53% | 1900 M☉ |
| `C_heavy50` | 5 : 5 | 500 × 1 + 500 × 10 M☉ | 91% | 5500 M☉ |

> 若老师本意是**质量比** 1:9 / 5:5，只需把 `run_all.sh` 里的 `-a 0.1` 改成
> `-a 0.011`（≈11 颗重星）、`-a 0.5` 改成 `-a 0.0909`（≈91 颗重星）即可，
> 脚本其余部分无需改动。

## 2. 物理量

### 2.1 弛豫时间

$$t_{rh} = \frac{0.138}{\ln(0.11 N)}\sqrt{\frac{N R_h^3}{G\,\bar m}}$$

由每个实现的**初始条件**直接计算（`run_all.sh` 调用 `calc_trh.py`）：

| 配置 | $\bar m$ [M☉] | M [M☉] | $t_{rh}$ [Myr] | $t_{end}=2t_{rh}$ [Myr] | 快照数 |
|---|---|---|---|---|---|
| `A_single`  | 1.00 | 1000 | 13.84 | 27.5 | 56 |
| `B_heavy10` | 1.90 | 1900 | 10.04 | 20.0 | 41 |
| `C_heavy50` | 5.50 | 5500 |  5.90 | 12.0 | 25 |

> **积分时长取 2 $t_{rh}$ 的理由**：题目要求 2–3 $t_{rh}$，取下限。
> 一来它落在题目范围内，二来它落在**数值可靠的区间内**——含 10 M☉ 重星的系统在
> 约 2 $t_{rh}$ 之后，PeTar 的 SDAR 时间变换会频繁退化（见 §2.4）。
> 实测对比：窗口取 50 Myr（= 4–9 $t_{rh}$）时，B 组 16 次尝试只有 2 次通过
> （12.5%）；收到 2 $t_{rh}$ 后升到 33%，配合自动重试即可集齐 3 个干净实现。
> 第一阶段（50 Myr 窗口）的完整尝试记录保留在 `attempts_phase1_50Myr.tsv`，
> 失败日志在 `evidence/_phase1_50Myr/`。
>
> 由于三个系统的 $t_{rh}$ 不同，各自的 2 $t_{rh}$ 对应不同的物理时长
> （27.5 / 20 / 12 Myr），因此所有对比图的**横轴统一用归一化时间 $t/t_{rh}$**，
> 三条曲线都在 $[0,2]$ 区间内，可直接对齐比较。
>
> 参考：等质量系统的完整核心塌缩需约 15 $t_{rh}$（≈ 200 Myr，作业 1 跑的就是这个量级），
> 远超本作业窗口——这正是"有/无黑洞"差异的体现。

### 2.2 质量分层诊断量

1. $r_{h,\rm heavy}/r_{h,\rm light}$ —— 重星与轻星各自的半质量半径之比。
   $< 1$ 表示重星比轻星更向中心集中。
2. $\langle m\rangle(<r_h)/\bar m$ —— 半质量半径以内的平均质量与整体平均质量之比。
   $> 1$ 表示中心富集重星。
3. $\langle m\rangle(<r)$ 沿半径剖面 —— 直接看不同时刻的质量分布。

### 2.3 数值可靠性判据

PeTar 的 SDAR 方法对"极紧双星"不保证经典哈密顿量守恒（PeTar README,
*Troubleshooting → Significant Hard Energy*）。失稳时系统会凭空获得能量、
由束缚变为不束缚，**但程序不报错、图像照样能出**。含 10 M☉ 重星的系统更容易
形成紧双星，风险更高，因此每个随机实现都先过能量自检：

- 跑到 $t_{\rm end}$
- $|\Delta E/E| < 5\%$
- $\max|{\rm Modify}|/|E_0| < 1\%$（`Modify` = 日志 `Physic` 行第 7 列）
- `*.hard_large_energy_*` 诊断文件数只作警告（官方文档：偶发的局部硬积分误差
  不影响整体演化），但设 10 个的兜底上限

不合格的种子自动丢弃、重抽重跑，证据存到 `evidence/`。

### 2.4 看门狗（本作业最关键的工程细节）

只做"跑完再查能量"是不够的。含 10 M☉ 重星的系统会形成成员数多达 20 以上的
紧多体系统，此时 PeTar 的 SDAR **时间变换**可能退化，表现为：

```
T: 2.8e-05  dT_err/T: 0.769  ds: 7.3e-09  ds_init: 0.004  |Int_err_cum/E|: 0.083  Step_count: 1000000
T: 1.2e-04  dT_err/T: 0.995  ds: 4.8e-10  ds_init: 0.004  |Int_err_cum/E|: 0.548  Step_count: 1000000
```

- `|Int_err_cum/E|` 从 $10^{-9}$ 一路涨到 0.5 以上（累计积分误差已达能量的 50%）
- `Step_count` 触到 `--ar-max-nstep` 上限（$10^6$）
- `ds` 比初始值小 6–7 个数量级，模拟几乎不再前进

**关键问题：PeTar 不报错、不退出，只是一直占着 CPU。** 实测这种状态可以持续
几十分钟而不产生任何新快照。如果采用"先跑完再看能量"的策略，整个流程会在这里
无限期挂住（本作业第一轮运行就踩了这个坑，两个任务空转了 40 多分钟）。

因此 `run_all.sh` 为每次积分配了看门狗，每 5 秒轮询一次：

| 触发条件 | 阈值 | 说明 |
|---|---|---|
| `\|Int_err_cum/E\|` 超限 | 0.1 | 积分器已发散，继续跑无意义 |
| 无新快照时长 | 360 s | 正常约 4–12 s 产生一个快照，360 s 即异常 |

触发任一条件即 `kill` 该次积分、记录原因、保存日志到 `evidence/`，然后重抽种子。

### 2.5 树时间步 dt_soft

用 PeTar 内置的自适应公式（`-s 0`）：

$$dt_{\rm soft} = 2.6\times10^{-4}\,\frac{G M}{\sigma_{\rm 3D}^3},\quad
\text{规整到 } 2^{-n}$$

它只依赖初始条件（$M$ 与三维速度弥散 $\sigma_{\rm 3D}$），因此**可复现**。
实测取值：A、B 为 $2^{-11} = 4.88\times10^{-4}$ Myr，C 为 $2^{-12} = 2.44\times10^{-4}$ Myr。

> 不用官方示例的 `petar.find.dt`：该工具按**墙钟时间**挑选"性能最优"的步长，
> 机器有负载时会给出显著偏小且不可复现的结果（作业 1 中实测从 0.0039 退化到
> 0.00024，慢 16 倍）。

## 4. 实现细节

### 4.1 为什么用 ASCII 快照

`petar -i 1` 让快照写成 ASCII（每行 20 列：质量 / 位置 / 速度 / 双星状态 /
搜索半径 / id / … / 总势能 / 软势能 / 邻居数）。`analyze.py` 用 `np.loadtxt`
直接读，从而可以**独立于 PeTar 的 Python 接口**计算任意诊断量
（按质量分组的半质量半径、累计平均质量剖面等）。

### 4.2 后处理

```bash
petar.data.gether  data
petar.data.process -G 0.00449830997959438 -s ascii -e \
                   -m 0.01,0.05,0.1,0.2,0.3,0.5,0.7,0.9,0.99 data.snap.lst
```

- `-s ascii`：输入快照是 ASCII（与 `-i 1` 对应）
- `-e`：额外计算各半径的势能与维里比
- `-m`：把默认的 5 档质量分数细化成 9 档，便于看核心区

`data.lagr` 与 `data.core` 是二进制，用 PeTar 自带的 Python 模块读：

```python
import petar, numpy as np
mf = np.array([0.01,0.05,0.1,0.2,0.3,0.5,0.7,0.9,0.99])
lag = petar.LagrangianMultiple(mass_fraction=mf, calc_energy=True)
lag.fromfile("data.lagr")
```

> ⚠️ 坑：`fromfile()` 不会从文件头自动识别质量分数列表，必须显式把
> `mass_fraction=` 传给**构造函数**，否则会按默认 5 档解析、列错位。

### 4.3 中文字体

`analyze.py` / `make_report.py` 都只接受**简体中文**字体（文泉驿微米黑），
并显式 `addfont()` 注册 `.ttc` 文件。不用 `Noto Sans CJK JP` —— 它是日文字形，
能显示汉字但会画出"错字"（如「径」的右上部在日文里是「ス」形）。

**题目只要求两幅图**（已生成）：

横轴为时间（Myr），竖虚线标出各系统各自的 $t_{end} = 2t_{rh}$。
另有归一化时间 $t/t_{rh}$ 版本在 `figs/extra/fig_rh_normalised.png`。

报告见 [`report/homework_2_report.pdf`](report/homework_2_report.pdf)（7 页 A4，
只含「研究思路 / 模拟配置参数 / 结果绘图对比与解说」三节），
数值汇总见 [`summary.txt`](summary.txt)。

三组配置各 3 个随机实现，取中位数：

| 量 | A 无黑洞 | B 重星 10% | C 重星 50% |
|---|---|---|---|
| $r_h$ | 0.99 → 1.00 pc（×1.00） | 0.99 → 1.08 pc（×1.10） | 1.00 → 0.96 pc（×0.96） |
| $r_c$ | 0.41 → 0.32 pc（×**0.78**） | 0.45 → **0.16** pc（×**0.34**） | 0.42 → 0.35 pc（×**0.84**） |
| $r_c/r_h$ | 0.32 | **0.14** | 0.37 |
| $r_{h,\rm heavy}/r_{h,\rm light}$ | 1.000（只有一种质量，无分层） | 0.92 → **0.27** | 0.96 → **0.53** |
| $\langle m\rangle(<r_h)/\bar m$ | 1.000 | 1.06 → **1.72** | 1.02 → **1.28** |
| $\max\|\Delta E/E\|$ | 1.4e−6 | 6.9e−5 | 1.5e−6 |

### 结论

1. **整体尺度不变**：三组 $r_h$ 末态相对初值变化都在 ±10% 以内。2 $t_{rh}$ 内发生的是
   **内部质量重分布**，不是整体膨胀。
2. **发生质量迁移**：含 10 M☉ 重星的两组，$r_{h,\rm heavy}/r_{h,\rm light}$ 从 ~0.95
   降到 **0.27（B）/ 0.53（C）**，即重星子系统比轻星子系统紧凑 2–4 倍；
   $r_h$ 以内的平均质量相对整体平均值分别上升 72% / 28%。
   单质量对照组两个指标恒等于 1.000——完美的空白对照。
3. **发生核心收缩**：无黑洞组 $r_c$ 只降到 ×0.78（且主要来自随机扰动），
   而 C 组 ×0.84、**B 组 ×0.34**。以 $r_c/r_h$ 计，B 组从 0.45 掉到 0.14。
   这是核心塌缩的早期阶段。
4. **反直觉但有物理意义**：重星只占 **10%** 的 B 组，分层与核心收缩比占 50% 的 C 组
   **更剧烈**。原因是重星是少数时它们形成一个"小而密"的独立子系统、内部弛豫极快，
   迅速塌缩成极紧凑的核心（文献里的"黑洞子系统"，BH subsystem）；
   而当重星占一半时，重星本身就是星团主体，"重星 vs 轻星"的对比反而没那么悬殊。
   **少量黑洞反而造成更极端的核心集中。**
